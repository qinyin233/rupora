## 已复现的问题与修复

- `!a` 选择 `!`、`甲🙂尾` 选择 `甲🙂`：Markdown 星号受 CommonMark
  边界规则限制，不能形成强调。保留普通 Markdown 路径；仅在它无法表达选区时，
  使用标准、无属性的 `<strong>` / `<em>`。没有修改解析器规则或增加可见空白。
- 原生投影只将平衡、同一 Markdown 层级内的规范标签转换为强调事件。
  代码、跨段、不匹配及带属性标签不会被当成上述格式包装。
- HTML 包装原先被自动链接的尖括号检测误认，编辑时会被剥除。
  自动链接现在要求开闭部分恰为 `<` 和 `>`。
- 格式内部回车关闭并重开包装；边缘回车放在包装外。插入点移到隐藏标签前时，
  光标也必须以实际插入点计算，不能沿用标签后的旧映射。
- 删除段落间隔不能吞掉未选中格式的隐藏闭合标记；分段再合并检查文字和样式。
- 混合 Markdown/HTML 包装取消某一种格式时，按整个选区包装链切换语义，
  防止外层移除后内层星号失效，或已有斜体被重复添加。
- 包装链匹配按源码范围一次建立索引，复杂度 O(N log N)；回归实际执行
  1024 层嵌套内的局部格式命令，而不只检查解析。
- 选区末尾未配对的字面反斜杠需补转义，否则会转义 HTML 闭合标签的 `<`。
  返回源码选区包含完整转义，视觉文本和选区不变。
  但选区若切开了反斜杠转义或硬换行语法，保留原源码操作路径，不能把语法字符
  错当成可见反斜杠。全量测试发现此区别，现有 39 项格式单元测试已重新通过。

## 源码往返约定

Undo 精确恢复原文，Redo 精确恢复命令结果。格式开关保留视觉文本、其他格式和
邻居，允许规范化当前选区的等价格式包装及必要转义。例如 `\a` 中选择反斜杠，
加粗再取消可能保留等价的 `\\a`；不能凭猜测删除转义字符。
预先存在的 `**` 和 `<strong>` 在取消后无法从纯文本区分，故两次 toggle
不保证恢复每一种原始写法；#33 已记录这一验收澄清。
