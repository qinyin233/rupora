# 段落点击跳动与空行输入修复

用户反馈：点击普通段落进入编辑会在下面多出一段空白；在该空白输入，内容却接到下一段开头。

## 复现与原因

桌面复现记录见 `PARAGRAPH-GAP-DESKTOP-2026-09-10.md`。原 release 中点击第一段后，后续两段整体下移约 43 像素；在新增空白输入 `GAP-INPUT`，结果成为 `GAP-INPUT第二段 KEEP-SECOND。`。

源码中，预览使用 Markdown 块的正文范围，编辑缓冲区却包含一直到下一块开头的分隔换行。所见即所得投影把这些结构换行全部显示成文本行，最后一行又映射到下一块开头。编辑与预览的外部留白、边框内边距及额外空行行高也不一致。

## 修复

- 正文编辑采用与预览相同的解析范围，保留源码中的块间分隔；两个结构换行不再显示成额外编辑行。实际多出的空行按正文行高显示。
- 真实空行的插入落点位于下一块之前，输入后保留下一段的分隔。删除一个可见空行仅删除一个源码换行。
- 统一普通文本、标题、引用、列表的预览与编辑间距；由实际排版高度决定编辑框高度，删除重复的行数估算函数。
- 文档末尾已有空行在预览和编辑状态均保持显示，点击末段不会突然展开。
- 隐藏分隔后的 Delete 在文本控件处理后续输入前执行，保证同一帧 `Delete + 输入` 与逐步输入结果一致；代码围栏所需换行继续受到保护。
- 保留回车后光标的源码位置，避免后续输入跳到下一段。修正行内格式末端的删除边界，退格不再吞掉粗体、斜体、删除线或行内代码的关闭标记。
- 段落边界的方向键可以跨过隐藏分隔；导航本身不修改文档，进入代码块时落到代码正文。
