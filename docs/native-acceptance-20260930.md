## I8：源码与分屏分别执行

分别从预先写入的 UTF-8 无 BOM、无尾随换行 `A🙂B` 开始，文件为
`target/acceptance-issue34-20260930/source-close-ime.md` 和同目录
`split-close-ime.md`。每种模式均单独通过系统对话框打开文件并聚焦正文。

| 操作 | 两种模式的实际结果 |
| --- | --- |
| A 后逐键 `z`、`w`，观察“中文”候选，空格确认 | `A中文🙂B`，保留未保存状态 |
| 再按 `z`，候选可见时点击标题栏关闭，确认框选择“否” | 窗口保留；候选消失，正文 `A中文z🙂B`；Ctrl+S 后磁盘相同 |
| 一次 Ctrl+Z | 只撤销 `z`，恢复 `A中文🙂B`，中文和 emoji 保留 |
| 按 `m`，Escape 取消 | 正文仍为 `A中文🙂B` |
| 逐键 `m`、`o`，选择“末”并空格确认，Ctrl+S | `A中文末🙂B`，下列基线哈希一致 |
| 再按 `z`，候选可见时切到计算器，再返回 | 候选消失，正文 `A中文末z🙂B`；Ctrl+S 后磁盘相同 |
| 一次 Ctrl+Z，再 Ctrl+S | 精确恢复 `A中文末🙂B`，文件哈希恢复到切换前基线 |

分屏中，右侧在预编辑期间保持已确认正文；确认、关闭取消、切换返回和撤销后，
左右两侧对应一致。取消关闭后可继续组合输入及保存，未观察到重复中文、emoji 损坏
或候选残留。源码模式也保留正确的正文与光标位置。

两个最终文件均为 15 字节：`41E4B8ADE69687E69CABF09F998242`，SHA-256：

`5f67de170641048656ed19af0eb76aaa4e88e38e4e8234e4afb2509fc14f543f`

本轮没有事件探针，不能仅凭字母 `z` 出现就推断新缺陷或宣称捕获了正式 Commit。
此前探针的事件分类见 [2026-09-27 记录](native-acceptance-20260927.md)，
不把旧事件轨迹冒充本轮证据。本轮可直接确认的是既有内容未丢失、新增字母可单独撤销、
后续输入和保存正常。两文件保存后正常退出 RUPORA，并确认窗口消失。
