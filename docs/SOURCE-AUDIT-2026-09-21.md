## 已修复问题

### 所见即所得输入与投影

- 完整替换图片时，源码可能残留图片目的地；删除图片可见标记时，也可能留下关闭语法。现在按图片包装范围处理，同时保留未选中 alt 内容、内部格式及外层链接。
- 编辑 `&amp;`、`&#38;` 等实体时，解码结果曾错误映射到实体名称内部，产生 `Xamp;` 等残留。现在把解码实体视为不可拆开的源码范围。
- 多字符实体的部分编辑会丢掉未选中的解码字符。现在保留两侧字符，转义字面标点并修正光标，防止 `>`、`<` 被重新解释成引用或 HTML。
- 从图片 alt 跨到相邻强调文本进行替换时，可能只删掉一侧格式标记；删除嵌套图片后面的文字时，可能吞掉内层图片目的地。现在完整处理被选中的包装语法，并保护未选中相邻包装的边界。除投影回归外，还保留了真实 egui 选区加输入的回归。
- 同帧粘贴、局部删除后按 Enter，曾绕过 URL 链接、列表续行或错误触发智能配对。现在分别保留 Text、Paste 和删除的语义，处理只移动光标的智能闭合符及无文本变化的编辑。
- 输入与格式快捷键在同帧到达时，命令曾提前作用于旧光标。现在先完成前面的输入再格式化；对夹在输入中间的单个格式命令，在同一次 egui 帧运行中完成后续输入。补充处理跳过后台任务，绑定原文档，覆盖源码、所见即所得、分栏、IME 和撤销重做。
- 移除 CRLF 代码块围栏时，正文末尾多计了一个 `\r`，导致格式切换失败。现在使用完整换行范围；覆盖空正文、中文、emoji、多行及两种围栏。

复审还拦住并修复了两处修复过程中的回归：图片删除后两侧强调标记贴合，需要经重新解析验证的不可见分隔；阅读模式或编辑器失焦时不能延迟格式命令，否则会悬挂命令或漏掉输入。对应失败用例已保留。

### 持久化与健壮性

- 工作区的扫描上限只计算最终显示的条目，非 Markdown 文件和空目录可能导致无界遍历。现在所有枚举项在过滤或递归前消耗共享预算。
- 恢复文件曾先按当前结构解析再检查版本，未来版本改变字段时会被错误隔离，并允许自动覆盖。现在先读取版本，未知版本保持原文件并阻止保存、清理；当前版本的损坏文件继续走隔离流程。
- Windows 新建文件保存前后，路径是否含 verbatim 前缀会改变锁身份。现在统一普通盘符和 UNC 路径的对应前缀，保留其他设备前缀。
- Windows 路径身份的有损 UTF-16 转换及 Unicode 多字符小写展开会合并不同文件名，导致另存为误写原文件。现在保留原生路径单位并使用 Windows 单单位大小写映射；真实文件操作回归覆盖既存、新建目标及锁。
- 首轮 Windows CI 发现新文件的父目录别名仍会改变创建前后的锁身份：文件不存在时没有展开短路径或目录链接。现在复用保存路径解析，先解析已存在的父目录再拼接文件名。新增跨平台父目录别名锁回归，独立验证真实 8.3 短路径及目录 junction 的创建前后身份一致。

## 验证边界

- egui 回归验证程序实际输入和渲染路径，包括 IME 事件；没有声称已手动操作所有系统输入法。
- 本地 fuzz 构建检查不能替代持续模糊测试；常规 push 的 CI 不运行定时 fuzz 作业。
- 快捷键同帧拆分只适用于编辑器已聚焦、单个格式命令、无鼠标/弹窗/文件操作且有补充布局次数的批次。多个命令或显式配置单次布局仍走既有路由，已检查不会缓存、重放或丢掉文字，未保证这些复杂批次与分帧执行具有完全相同的格式结果。
- Windows 路径回归验证了本机文件系统；未声称已验证远端 UNC 或启用区分大小写的特殊卷配置。
- 复审和回归能验证已覆盖的行为，不能证明任意 Markdown 与任意事件序列都不存在缺陷。
