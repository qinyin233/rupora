## D01 / P1：删除代码块后的整段正文，再输入会破坏闭围栏

**最小已验证步骤：**

1. 打开专用夹具，使用“写作”模式。
2. 点击 Python 代码块后独立段落 `代码后正文 KEEP-AFTER。`。
3. 按 Ctrl+A。此构建只选当前段落，所选文本可从可访问性状态确认。
4. 按 Delete。段落消失，焦点变成“从第 7 行开始的所见即所得编辑块”，即前面的代码块。
5. 不再点击鼠标，输入 `REPLACE-PARA`。

**预期：** 新文字留在被删除段落原位置，作为代码块后的普通正文；代码闭围栏与后续结构完整。

## D02 / P2：写作模式的全文快捷键局限于当前块

**步骤及实际：**

- 点击 Python 代码块中间，Ctrl+End 只移到 `print(items)` 行末，视口仍在顶部。
- 从代码末行按 Down，能够进入代码后的正文，这是正常对照。
- 在该正文中 Ctrl+Home/End 只移动到当前块首尾；Ctrl+End 后 PageDown 未造成可见跨块或翻页移动。
- Ctrl+A 只选 `代码后正文 KEEP-AFTER。`；再次 Ctrl+A 仍然只选该段。可访问性 `selected_text` 精确为该段文字。
- 源码模式 Ctrl+End 能正常滚动到 162 行文末 `END-KEEP`。

**预期：** 文档编辑器提供一致、可发现的全文首尾导航与全选。若产品有意先全选块，至少第二次全选应扩展到整篇，并说明该行为。

**证据：** `target/product-desktop-evidence/01-block-select-all.png` 和 `.json`。

**影响与建议：** 用户难以通过惯用快捷键选择或导航长文，两种编辑模式行为不一致。以文档选区统一处理 Ctrl+Home/End、Ctrl+Shift+Home/End 与 Ctrl+A；PageUp/PageDown 的跨块语义一并核对。此项预期基于桌面编辑器常用交互，是否保留块级首轮全选属于产品决策。

## D03 / P2：模式切换保持旧视口，没有显示当前光标块

**步骤：**

1. 在源码模式聚焦编辑区，按 Ctrl+End。
2. 等待滚动完成，确认 `END-KEEP` 已在屏幕底部可见。
3. 点击顶部“写作”。

**预期：** 写作模式显示同一个文末位置，便于继续编辑。

**实际：** 页面回到此前写作模式的文档顶部；重复观察后仍显示文首。可访问性树却保留“从第 161 行开始的所见即所得编辑块”，焦点为窗口根区域，当前编辑块不在视口中。

反向对照也出现旧视口保留：在写作模式滚到 Unicode 区域并编辑、撤销后，点击“源码”，恢复的是之前源码模式的文末视口。

**证据：** `target/product-desktop-evidence/03-mode-switch-caret.png` 和 `.json`。

**建议：** 以当前文档源码光标或选区为切换定位锚点，模式切换完成布局后滚动到对应块；若主动选择每种模式独立保存视口，也应提供清晰的“定位到当前光标”动作。
