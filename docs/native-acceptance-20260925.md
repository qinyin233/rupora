## 输入与历史验证

以下操作分别在源码、分栏模式执行，两种模式均得到表中的结果。

| 检查 | 操作与实际结果 |
| --- | --- |
| 行首输入 | 第一行 Home，逐键 ni，空格确认候选“你”，得到 `你甲🙂\n\n乙` |
| 行尾输入 | End 到第一行 emoji 后，逐键 mo，空格确认候选“末”，得到 `你甲🙂末\n\n乙` |
| 两次提交的撤销 | 两次 Ctrl+Z 依次恢复 `你甲🙂\n\n乙`、`甲🙂\n\n乙` |
| 两次提交的重做 | 两次 Ctrl+Shift+Z 依次恢复“你”和“末”，原有 emoji、空行、第二段完整 |
| 跨段选区 | Ctrl+End、Ctrl+Shift+Home；可访问 selected_text 确认为完整 `你甲🙂末\n\n乙` |
| 跨段替换 | 逐键 xin，空格确认候选“新”，全文变为 `新` |
| 替换的历史边界 | 一次撤销恢复原两段，一次重做恢复 `新`，再撤销恢复原两段与选区 |
| 跨段取消 | 在恢复的选区上按 z，再 Escape；全文恢复 `你甲🙂末\n\n乙`，没有拼音残留 |

分栏模式额外通过截图核对：ni、mo、xin 的候选框仍显示时，右侧预览保留已提交正文；
空格确认后，右侧同步显示新正文。跨段替换确认后两侧均只显示“新”；取消 z 后，
两侧均恢复两段原文。

## 写作模式：任务列表、粗体、BOM 与 CRLF

继续使用上述 Windows、微软拼音和同一解包程序，新增独立合成文件
`target/native-ime-transaction-fixtures/写作任务列表CRLF-20260925.md`。
初始磁盘字节为 UTF-8 BOM 加 `- [ ] 甲🙂\r\n\r\n**粗体🙂乙**`，
37 字节，SHA-256 为
`c5230060e1be8df29029e2008808c5fd30866d8764273c5db5feac529db7c544`。
此处 `\r\n` 表示实际 CRLF。

通过系统打开对话框加载后，状态栏显示 UTF-8 BOM、CRLF。切到写作模式，
任务框和粗体段落分别渲染；点击任务项 emoji 后逐键 ni，观察候选框并空格确认“你”，
任务项显示 `☐ 甲🙂你`。点击粗体段落 emoji 与“乙”之间逐键 mo，观察候选框并空格
确认“末”，段落显示粗体 `粗体🙂末乙`。两次 Ctrl+Z 分别撤销“末”和“你”，
两次 Ctrl+Shift+Z 分别重做；源码模式核对完整正文为
`- [ ] 甲🙂你\n\n**粗体🙂末乙**`，任务标记与强调标记未损坏。

Ctrl+S 后读取真实磁盘字节：BOM 为 `EF BB BF`，两个换行均为 CRLF，无裸 LF，
43 字节；解码结果恰为 `- [ ] 甲🙂你\r\n\r\n**粗体🙂末乙**`，
SHA-256 为
`265966809122722f8cc6c490c77f7e1ff99c1e60ce785598e04891311a160f61`。
正常退出并从同一程序重启，源码仍为两段完整 Markdown；切回写作模式，
任务框未勾选、粗体和两处 emoji 正确显示。点击任务框使其勾选，再按 Ctrl+Z，
未勾选状态和全部正文恢复；源码确认仍为已保存的内容。复测后正常退出。

该场景补充真实所见即所得输入、渲染和编码保持证据；未发现新缺陷，
也不能代表其他 Markdown 结构或输入法已完成验收。

## 源码模式：未确认候选与保存边界

继续使用上述 Windows 11 x86_64、微软拼音和同一 NSIS 解包程序。
独立合成文件 `target/native-ime-transaction-fixtures/待确认保存-20260925.md`
初始正文为 `A🙂B`，UTF-8 无 BOM、6 字节、无尾随换行，SHA-256 为
`dabeeb0b851f14d5cad4f9b871a03bb40b6dad9950aef774f7af7e7b0a518715`。

在 `A` 后将光标置于 emoji 前，逐键输入 ni，系统候选框仍显示时，
源码编辑框的可访问文本是临时的 `Ani🙂B`。此时按 Ctrl+S，
候选框仍在、磁盘仍精确为原始 `A🙂B`（6 字节、相同 SHA-256）。
按 Escape 后，界面正文恢复 `A🙂B`，磁盘也保持原样。
重新逐键输入 ni，并用空格确认候选“你”后，界面为 `A你🙂B`、出现未保存标记，
但磁盘仍是 `A🙂B`。再次按 Ctrl+S 后，未保存标记消失；磁盘精确为
`A你🙂B`，UTF-8 无 BOM、9 字节、无尾随换行，SHA-256 为
`2f4f53ebc0801b37ae92fc0f5eb3434cb6234cfdb72d4ba74cf6868ad416bf90`。

保存后按一次 Ctrl+Z，界面恢复 `A🙂B`；一次 Ctrl+Y 后恢复 `A你🙂B`。
正常退出、确认窗口消失并从同一程序路径重启后，源码正文仍为 `A你🙂B`。
这证明该用例的未确认预编辑未进入保存文件，确认后的提交可保存、撤销和重做；
不推断 Ctrl+S 在候选框显示时是否实际执行了无改动保存。

没有执行强制退出的原生恢复实验：程序的会话与恢复快照位于当前 Windows
用户的漫游数据目录，改写进程 `APPDATA` 环境变量不足以隔离；当前实例还打开真实用户会话。
这项实验需要独立 Windows 账户或虚拟机。上述源模式结果也不代表写作、分栏模式的
相同保存边界或其他输入法已验收，#6 保持开放。
