# 源码审计与 CI 故障修复记录

日期：2026-09-09。基线提交：`19ec2874b2bd43732fa6d1e9909125ab71c700a4`。
范围：`native/src` 核心模块及其调用链、测试与 fuzz 目标、构建脚本、打包脚本和 GitHub Actions 配置。
本记录包含此前源码审计的修复，以及本次从 GitHub Actions 失败日志复现的 WYSIWYG 崩溃修复。

## CI 失败原因与修复

[Native Rust CI #15](https://github.com/qinyin233/rupora/actions/runs/34099943888)
在 2026-09-07 定时运行中失败。Windows、Linux、macOS 的测试/Clippy/release 构建和安全/性能任务均成功；
失败发生在 `Run fuzz targets` 的 `wysiwyg_projection` 执行阶段，fuzz 二进制本身已编译成功。

日志报告 `slice index starts at 9 but ends at 8`，退出状态为 77。
原始输入的 Base64 为 `LisKICA9KwogICAkICAgICAgIGI=`，样本标识为
`crash-d39e15824b6db23cc1053c3ad0edb04a3ed70947`。

本地用 `cargo test --locked --test wysiwyg_fuzz_regressions` 复现了相同越界，
调用栈定位到 `VisualProjection::apply_edit` 的 `String::replace_range`。
继续缩小后，`"+ \n  "` 就能产生错误的投影：额外换行使源码映射从尾部倒退到尚待追加的空白，
跨过这一位置的选区会得到反向范围。扩展测试还复现了裸 CR 与制表符组合的同类问题。

修复位于 [wysiwyg.rs](../native/src/wysiwyg.rs)：

- 块结束时将换行映射到实际换行符末尾，保留其后的缩进供空白投影处理。
- 合成换行的源码位置不早于已映射内容。
- 已被解析文本覆盖的尾部换行不再重复追加。

[回归测试](../tests/wysiwyg_fuzz_regressions.rs)包含原始 fuzz 输入、最小列表编辑场景，以及
列表/引用/标题/段落/代码块与 LF/CRLF/CR、空格/制表符组合的 72 个场景。
测试检查选区顺序、源码范围和删除尾部空白的实际编辑结果。
三项测试在修复前失败、修复后通过，并由现有的每次 push 测试任务执行。

CI 同时启用 fuzz 调用栈，并在失败时上传 `fuzz/artifacts/`，保留 14 天。
没有关闭 fuzz 或放宽其失败条件。

## 源码审计修复清单

| 问题 | 修复与验证 |
| --- | --- |
| 本地图片路径含中文、空格、特殊字符时加载失败 | 按已安装 egui 文件加载器的输入约定传递原生路径；使用真实加载器验证。 |
| 行命令误修改选区结束位置所在的下一行 | 统一计算排他选区覆盖的行范围，验证格式化和缩进。 |
| 光标不在表格内时修改了第一张表 | 只返回包含光标的解析器表格范围。 |
| 代码块或 Setext 标题被误识别为表格 | 使用 Markdown 解析事件识别顶层表格。 |
| 表格吞入后续含竖线的标题/其他块 | 表格行严格限制在解析器提供的范围内。 |
| 无外边框表格行末的转义竖线丢失 | 区分转义竖线与真实列边界。 |
| 保存后继续输入仍合并进旧撤销组 | 成功保存、撤销和重做关闭当前输入合并组。 |
| 普通粘贴覆盖选区时内容丢失 | 仅在智能链接转换成功后采用转换结果，保留普通粘贴。 |
| 未命名标签切换后选区丢失 | 按稳定文档 ID 保存临时选区与滚动状态。 |
| 关闭后台标签扰乱当前标签选区 | 关闭前保存当前视图，并按文档 ID 恢复。 |
| 多文件重载时当前编辑器状态未重置 | 跟踪本轮是否重载过活动文档，清理过期视图、跨块指针和输入状态。 |
| 重复标题、显式 ID 和自动后缀发生锚点冲突 | 预留显式 ID，并对最终输出的标题 ID 统一去重。 |
| Windows 打印路径被 PowerShell 当作命令语法解析 | 用子进程环境变量传入字面路径；验证空格、引号和元字符。 |
| 大量 Unicode 匹配的批量替换明显卡顿 | 收集字节范围后一次构造输出，避免重复全文件扫描和移动。 |
| 跨块选择后同帧多个输入事件丢失 | 按次序消费事件，并规范化粘贴换行。 |
| 扩展返回 CRLF/CR 破坏文档内部 LF 约定 | 在应用扩展编辑前统一换行，防止保存时重复 CR。 |
| WYSIWYG 尾部空白映射倒退导致 CI fuzz 崩溃 | 修复换行与尾部缩进的映射；原始 fuzz 输入加入普通测试。 |

此前 16 类修复新增 16 项自动回归测试和 1 项手动性能测量；本次 CI 修复新增 3 项自动回归测试。
核心回归集中在 [audit_regressions.rs](../tests/audit_regressions.rs)及应用模块内部测试。

## 冗余代码清理

- `app.rs`、`wysiwyg.rs` 共用 `editing::char_to_byte`，删除两份重复字符索引转换。
- 表格识别复用 Markdown 解析器，删除重复的行扫描结构与分隔行识别实现。
- 删除与 egui 文件加载约定不匹配的路径 URI 转换助手。
- 行选区范围计算统一复用；删除查找路径中多余的字符起点封装。
- 查找与批量替换共用字节匹配逻辑，移除逐匹配重新扫描全文的路径。

## 验证结果

本地环境为 Windows x86_64，Rust 1.93.1。远程失败运行使用应用测试 Rust 1.92.0 和 fuzz nightly。

| 验证 | 结果 |
| --- | --- |
| 原始 CI 崩溃输入 | 修复前相同越界；修复后通过。 |
| `cargo test --all-targets --locked` | 264 项通过，2 项忽略；4 个 Criterion 冒烟用例成功。 |
| `cargo clippy --all-targets --all-features --locked -- -D warnings` | 通过。 |
| `cargo deny check --hide-inclusion-graph` | advisories、bans、licenses、sources 均通过；上游多版本依赖仍为警告。 |
| `cargo check --manifest-path fuzz/Cargo.toml --bins --locked` | 三个 fuzz 目标编译检查通过。 |
| `cargo build --release --locked` | 通过，生成 `target/release/rupora.exe`。 |
| `cargo run --release --locked --example perf_guard` | 全部通过：解析 0.020 秒、块协调 0.027 秒、记录编辑 0.003 秒、HTML 导出 0.038 秒、2.5 万次替换 0.001 秒。 |
| `cargo fmt --all -- --check`、`git diff --check` | 通过；两个 `Cargo.lock` 均无变化。 |

手动性能测量使用同一 debug 模式输入：`"中文 Aa 🙂\n".repeat(25_000)`，忽略大小写将 `aa` 替换为 `替换`。

这是一组本机测量；可重复的 release 回归预算已加入 [perf_guard.rs](../examples/perf_guard.rs)，上限为 1 秒。

本地验证日志保存在被 Git 忽略的 `target/ci-*.log`；失败样本与回归断言已写入源码测试，
复现不依赖这些本地日志。
