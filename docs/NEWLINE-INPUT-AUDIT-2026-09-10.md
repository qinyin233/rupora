# 换行、空段落与代码块边界修复记录

日期：2026-09-10。范围：所见即所得编辑器的段落索引、输入事件、源码与显示光标映射，以及相应的桌面回归。

## 统一的操作规则

- 普通段落中 Enter 创建下一段；Shift+Enter 在当前段内换行。
- 连续 Enter 创建可单独点击和编辑的空段落。对应次数的 Backspace 能恢复原文，不吞掉上一段末尾字符。
- 列表、任务列表和引用继续使用各自的续行、退出规则；代码块内 Enter 插入代码换行。
- 方向键跨过段落和代码块边界时只移动光标。删除空代码块保留后面的空段落和正文。
- 源码模式仍直接编辑 Markdown 换行；已有的两个尾随空格或反斜杠硬换行语法继续支持。

## 复现与修复

| 场景 | 复现的错误 | 修复方式 |
| --- | --- | --- |
| 文首 Enter | 源码出现换行，画面却没有可编辑的空段落 | 在块索引中明确表示空段落，提供独立的光标位置 |
| 连续 Enter 后输入 | 输入文字时光标或后文额外下移一行 | 空段落预览与编辑使用相同高度，输入直接填入该段落 |
| Enter 后 Backspace | 连续两次 Enter、两次 Backspace 可能把 FIRST 变成 FIRS | 按逻辑段落边界删除分隔符，分开处理空段落与正文 |
| 点击空白段落 | 输入接到下一段，或空编辑框导致后文上移 12 像素 | 全行点击区域、独立编辑范围与最小行高保持一致 |
| 同一帧连续输入 | Text→Enter→Text 与分帧操作产生不同 Markdown | 在创建编辑块前按顺序应用 Enter，重新解析后再处理后续输入 |
| 加粗、斜体、行内代码中 Enter | 格式标记跨段失效，直接显示星号或反引号 | 拆分时闭合并重新打开格式；退格合并时合并相同格式 |
| 连续 Shift+Enter | 空白硬换行被 Markdown 当作段落分隔，输入后布局改变 | 空行使用反斜杠硬换行语法；保留对应的编辑行 |
| 连续硬换行尚未输入文字 | 桌面实测发现末尾反斜杠短暂显示 | 投影隐藏解析器在段尾暂时视为文字的硬换行标记 |
| 只有空格的文档 | Enter 后输入的位置被强制移到开头 | 空白文档的编辑范围保留已有空格及光标位置 |

新空段落模型的回归还捕获了旧代码中“空块一定是文末”的假设：删除空代码块可能清空后文，双击退出代码块可能触发 panic。两条路径均改为使用相邻段落的真实位置，并加入专门回归。

移除了把段落分隔符隐藏在上一段编辑缓冲区的旧投影实现、额外空行计算函数，以及相应的重复 Select All 补偿代码。

## 桌面实测

通过 computer-use 在独立的 `RUPORA — Newline QA` 窗口操作，使用当前项目源码、单独的恢复存储与测试文档。测试入口位于 `target/newline-desktop-qa`，不进入正式产品源码。

1. 点击 FIRST：NEXT 和后续内容位置保持不变。
2. FIRST 段尾 Enter，再输入 NEW：生成独立段落；输入 NEW 时 NEXT 保持原位置。
3. 连续两次 Shift+Enter 再输入 SOFT：仍在同一段内，后续段落没有额外移动。
4. 从代码最后一行按 Down：光标进入 END-KEEP 开头；源码行数保持 18 行。
5. 文末 Enter 两次，再 Backspace 两次：行数 18→20→22→20→18，END-KEEP 全部保留。
6. 修复桌面发现的尾部反斜杠显示问题后重新构建测试程序；连续两次 Shift+Enter 的空行不再出现标记，输入 CHECK 时后文位置不变。
7. 通过应用保存测试文档，再读取文件核对 Markdown 内容及代码块边界。
