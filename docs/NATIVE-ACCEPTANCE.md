# 原生输入法与安装包验收

对应 [#6](https://github.com/qinyin233/rupora/issues/6)。本页是执行协议和记录模板，
**尚无平台在本页完成验收**。egui 事件注入、源码审查和 CI 构建不能填写为原生验收通过。

2026-09-24 已开始 [Windows 原生验收](native-acceptance-20260924.md)：写作模式
I1/I4 通过，I3 发现真实输入法选区替换缺陷；修复与剩余验收分别记录，整个平台尚未通过。

## 每次执行必须记录

- 日期、执行人、操作系统版本与架构、显示缩放比例。
- 输入法名称、版本、语言、布局；至少实际执行中文组合输入。第二种组合输入法未执行时注明。
- 应用版本、源码提交、安装包名称、下载地址、SHA-256、安装或解包方式。
- 平台代码签名状态；更新清单签名和 GitHub 来源证明分别记录，不能代替平台签名。
- 用例编号、视图模式、精确操作、预期与实际正文、保存后文件、截图或录屏证据路径。

待验收构建须包含 #2、#3、#4 和后续投影修复。`v2.0.0-alpha.3` 的既有发布包不包含
这些后续提交；不能拿旧安装包的结果证明新修复。开发包也须记录提交和文件哈希。
包的来源、签名与校验步骤见 [RELEASE.md](RELEASE.md)。

## 隔离数据

使用独立测试账户或虚拟机和新建的测试目录，只放合成 Markdown、图片和草稿。
保留本次执行使用的应用数据目录与恢复快照。不要用个人文档做强制退出或恢复测试。
故意终止进程前记录确切测试进程及测试目录；不得终止其他编辑会话。

## 用例

以下输入测试在源码、所见即所得和分屏模式分别执行。Markdown 格式命令另检查源码，
不能只看最终画面。每次用新文档开始，记录每一步的正文和选择区。
I1/I2 的 `A🙂B` 应预先写入合成测试文件并重新打开，以空的撤销历史开始；
不要先在编辑器中键入底文本再紧接组合输入，以免连续输入合并改变 I4 的撤销基线。

| 编号 | 操作 | 验收要点 |
| --- | --- | --- |
| I1 | 打开预先准备的 `A🙂B`，在 A 后通过系统输入法预编辑并选择“中文”，确认候选 | 预编辑位置跟随光标；提交后源码恰为 `A中文🙂B`，无重复拼音或候选文字 |
| I2 | 同样位置开始预编辑，按 Escape 取消，再输入“末”并确认 | 取消后仍为 `A🙂B`；下一次提交得到 `A末🙂B`；组合状态没有残留 |
| I3 | 在 `A中文🙂B` 中选择“文🙂”，通过输入法替换为“新” | 得到 `A中新B`，完整删除 emoji；方向键和反向选择不切断字符 |
| I4 | 对 I1 的最终提交执行一次撤销，再重做 | 恢复提交前和提交后正文；预编辑更新没有变成多份已提交内容，选区位置正确 |
| I5 | 粘贴 `甲🙂`、换行、`乙`，在行首/行尾输入；跨行选择替换 | 每行文字和 emoji 完整；换行、选区与光标一致；撤销/重做能恢复对应状态 |
| I6 | 提交文字后切换视图和文档，再切回；另记录预编辑中切换的行为 | 已提交文字不丢失；组合文字遵守系统实际提交/取消结果，不进入另一篇文档或重复出现 |
| I7 | 选择普通文本，依次加粗、斜体、链接，再逐项撤销/重做；重复两次加粗 | 命令不丢失；两次加粗恢复原文；链接快捷键不能删除段尾；源码与显示对应 |
| I8 | 预编辑时切到另一窗口、恢复焦点；对含未保存文字的测试窗口发起关闭并取消 | 不丢失已提交内容，不残留幽灵预编辑；取消关闭后可继续输入和保存 |
| P1 | 安装或解包指定资产，从该安装位置启动，再通过文件关联打开测试 Markdown | 实际运行的是记录的构建和架构；文件只打开一次，中文路径可用 |
| P2 | 保存含中文、emoji、多行与格式的文档，退出并重新启动，从磁盘重新打开 | 磁盘正文、编码、换行及渲染符合预期；修改保存到所选文件 |
| P3 | 用有已保存基线的合成文件编辑出新草稿，确认恢复快照已写出，再终止确切测试进程并重启 | 恢复出的草稿与已写出的快照一致，磁盘原文未被静默替换；未写入快照的最新输入另行记录 |
| P4 | P3 已确认快照写出并终止编辑器后，保留快照不变，由另一进程修改磁盘文件，然后重启恢复 | 可用草稿与外部修改均得到保留或明确冲突；不得用旧快照静默覆盖磁盘版本，恢复后重新读取磁盘确认未被改写 |

P3/P4 是进程终止后的产品验收，不能证明真实断电或设备故障时的数据持久性。
自动化提交边界测试另由 [#7](https://github.com/qinyin233/rupora/issues/7) 跟踪。
核对快照时，可通过“帮助 → 打开诊断日志目录”找到 `logs` 的父目录，读取其中的
`recovery.json`，确认当前合成草稿的唯一标记和完整正文已保存，再保留副本并终止测试进程。
只等待数秒不能证明快照写入成功；不要直接修改恢复文件。
