# Issue tracker: GitHub

Issues and specifications live in https://github.com/qinyin233/rupora/issues.
Confirm the repository against `git remote -v` before writing to the tracker.
Use the authenticated GitHub connector, or `gh` when installed. Search existing
issues before creating a duplicate. Use structured body arguments or a UTF-8
body file for multiline descriptions; never interpolate issue text as shell code.

- Read the issue body, labels and comments before acting.
- Record a concrete reproduction, expected behavior and acceptance criteria.
- Link fixes and verification evidence before closing a bug.
- Keep unverified follow-up work open; green CI is not proof of full product reliability.
- When a skill says to publish to the issue tracker, create or update a GitHub issue.
- When a skill says to fetch the relevant ticket, read the issue and comments.

**PRs as a request surface: no.**
