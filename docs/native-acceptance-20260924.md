## 原生结果

模式：写作（所见即所得）。通过系统打开对话框打开 UTF-8、无末尾换行的
`A🙂B` 测试文件，未通过程序接口注入编辑器事件。

| 用例 | 实际操作与结果 | 状态 |
| --- | --- | --- |
| I1 | 点击 A 后，逐键输入 `zhongwen`，观察到拼音预编辑和“中文”候选；空格确认得到 `A中文🙂B` | 通过 |
| I4 | 对上述提交 Ctrl+Z 得到 `A🙂B`，Ctrl+Shift+Z 得到 `A中文🙂B` | 通过 |
| I3 | 光标右移过 emoji，Shift+Left 两次，可访问选区确认为 `文🙂`；逐键输入 `xin`，预编辑为 `A中xinB`；空格确认后实际为 `A中新文🙂B`，预期 `A中新B` | 失败 |

I3 的前后文本同时得到窗口截图及可访问正文确认。失败没有写回磁盘。
复测前通过撤销恢复 `A🙂B` 并正常退出旧程序。此次失败后的历史记录还出现了
包含空格的中间状态，修复构建须重新检查实际撤销，不能直接沿用 I4 的结果。

## 回归与修复

`ime_clear_before_commit_replaces_the_original_selection` 在应用级事件入口重放
Windows 的空 Preedit 紧接非空 Commit，修复前确实得到相同的
`A中新文🙂B`。winit 0.30.13 的 Windows `WM_IME_COMPOSITION` 和
`WM_IME_ENDCOMPOSITION` 路径会连续发出这两个事件。

取消处理不再把这一对事件当成独立取消，而是交给 TextEdit 处理仍保留的
预编辑缓冲区。真正取消后跟普通输入的原有回归继续保留。新测试覆盖源码及写作
编辑路径、插入及选区替换、多帧预编辑、末尾空 Preedit，以及一次撤销/重做。

修复后的原生复测、其余输入用例、保存/重启/恢复和所有其他平台仍待执行。
