# 可靠性改进与验收

目标是让原生 Markdown 编辑、保存和恢复的关键行为可验证、失败可复现。
测试通过代表已覆盖场景通过，不代表软件不存在未知问题。

## 行为契约

- 编辑器持有键盘输入时，输入按实际事件顺序作用于原文档；批次、重绘次数或渲染模式不能使格式命令消失，
  也不能让命令键成为删除正文的默认 TextEdit 操作。
- 编辑验证同时检查正文、带方向的选区、文档身份与撤销/重做边界。
  IME 的预编辑、提交、取消分别验证，不将中间组合文字当作已提交正文。
- 保存失败保留本地草稿、历史、路径和编码。新目标不能覆盖并发创建的文件；
  已有目标在提交前复核磁盘版本。普通文件系统检查加原子替换不是严格的跨进程 CAS。
- 文件路径规范化必须保留文件身份。特别是 Windows verbatim 路径不能因去掉前缀
  而变成另一个文件；普通路径别名仍应共享文档锁。
- 过期后台结果不能写入新文档版本或另一篇文档。关闭、另存为及撤销到相同正文
  不得绕过版本校验。

## 证据分层

1. **纯函数和属性测试**：验证 UTF-8 字节边界、字符索引、投影、历史补丁与格式性质。
2. **产品事件回放**：通过生产 App、EditorSurface 和 egui 输入路径复现正文、选区和状态变化。
3. **文件系统和进程测试**：在隔离目录验证实际文件、锁、保存失败及恢复。
4. **原生桌面和安装包验收**：实际系统输入法进入原生窗口，运行发布产物并验证重启后数据。

第一至三层不能代替第四层。源码审查、fuzz 构建成功、签名更新清单和构建来源证明，
也分别不能代替行为测试、实际 fuzz 运行、操作系统代码签名和安装后验收。

原生输入法、实际安装包与各平台的执行记录使用 [原生验收协议](NATIVE-ACCEPTANCE.md)。

输入回放保留了真实指针按下、弹窗等场景的原生路由，尚未证明所有混合输入的全序。
每帧最多 8 个 pass 约束计算量，但持续超量输入的队列没有硬内存上限。
已有保存目标的最终检查至替换，以及原生保存对话框返回至目标快照，仍有竞态窗口。
UNC 路径目前只有规则测试，没有真实网络共享验收。

基础命令及性能预算见 [QUALITY.md](QUALITY.md)，现有模块约束见
[ARCHITECTURE.md](ARCHITECTURE.md)。上游实践与本仓库基线差距见
