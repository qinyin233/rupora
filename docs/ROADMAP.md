# RUPORA 2 完成情况与路线图

本文区分“已经可用”和“仍需专用编辑器模型”的能力，避免把原生预览误称为完整所见即所得。

## 本次已经逐项完成

1. **可靠文档状态**：精确 dirty 判断、原子保存、另存为回滚、外部修改冲突保护。
2. **恢复能力**：定时崩溃快照、恢复未保存文档、恢复上次文件和工作区会话。
3. **编辑效率**：查找/替换、大小写选项、粗体/斜体/链接/标题/列表/引用/代码格式命令。
4. **大纲导航**：标题提取、可点击跳转、Unicode 字符位置映射和编辑器滚动定位。
5. **工作区**：递归 Markdown 目录树、刷新、忽略构建目录和安全的扫描上限。
6. **资源上下文**：相对图片、相对 Markdown 链接、本地附件，以及文档目录基准 URI。
7. **工程发布**：36 项单元测试、严格 Clippy、三平台 CI、应用图标和可重复安装包。
8. **原生混合编辑**：基于 `pulldown-cmark` 源码范围划分顶层块；当前块编辑源码，其余块原生
   排版；块修改回写同一 `Document`，并与查找、格式化、大纲的全局字符位置共同工作。
9. **统一编辑历史**：普通输入、混合块输入、格式化、替换和任务列表共用文档级撤销/重做；
   历史存储最小文本补丁而不是全文快照，连续输入可合并。
10. **稳定块身份**：未变化内容作为锚点，相邻变化块进行身份协调，前方插入或块内编辑后
    `BlockId` 保持稳定。
11. **外部文件监控**：低开销定时探测；干净文档自动重载，脏文档显示冲突处理入口。

## 混合编辑的下一阶段

这些任务不是再嵌一个浏览器控件即可解决，而需要继续扩展原生编辑模型：

- 建立“排版字形位置 ↔ Markdown 源字符”双向映射，让点击文本落到准确字符而不是块首。
- 把跨块选择、拖拽和粘贴形成的多个变更合并为一个复合事务。
- 为表格提供单元格编辑模型，并处理列宽、对齐和跨单元格选择。
- 对超大文档使用增量解析和可视区域渲染，避免每帧扫描全文。
- 完善输入法组合文本、辅助功能和双向文本的回归测试。

## 尚未迁移的扩展能力

- 数学公式的纯原生排版与编辑
- Mermaid 等图表的安全原生渲染
- PDF 导出与分页样式
- 拼写检查、语言服务和插件 API

这些项目保持为明确的后续工作，不会通过恢复 WebView 依赖来“快速实现”。
