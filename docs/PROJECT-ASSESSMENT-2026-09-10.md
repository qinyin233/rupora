# 项目整体评估与架构升级

本轮通过 `ask-matt` 定位 `improve-codebase-architecture`，结合 `codebase-design` 评估模块深度与接口成本，使用 `domain-modeling` 记录文档术语。范围包括原生应用入口、文档与会话、编辑与呈现、系统操作、扩展、恢复、导出、测试及构建流程。结论依据源码调用链和行为回归，不以文件长度或测试数量给项目打分。

## 总体判断

当前应继续沿用 Rust / egui 原生框架。编码、原子保存、历史补丁、可逆 Markdown 投影、恢复存储和进程外扩展已具备实际职责，另换 UI 技术栈没有证据支持。第一轮拆开 App 后，主要问题转为跨模块的状态约定：谁判断旧结果还能否提交，谁处理外部文件变化，谁知道渲染依赖何时失效。

本轮选择把这三个概念做成更深的 module。它们都有两个以上真实调用入口；删除这些 module 会让规则重新散落在调用方，符合 codebase-design 的 deletion test。没有新增第三方依赖、全局事件总线或多 crate 框架。

## 逐项评估

| 范围 | 有效的现有设计 | 发现的问题与处理 |
| --- | --- | --- |
| 文档模型与历史 | UTF-8 字符位置、内部 LF、最小历史补丁、延迟分析、原子保存和文件锁 | 正文相等不足以表示编辑上下文相同；新增单调版本、只读快照、原子编辑与条件提交 |
| 文档会话 | 活动标签使用稳定文档身份，关闭左侧标签不会误选异步目标 | 扩展和表格重复实现查找/比较/记录；统一进入 Session 条件编辑入口，删除重复定位函数 |
| 编辑器 | 单一 EditorSurface 管理 IME、光标、跨块选区、文档书签；保留惰性 TextEdit 缓冲 | 命令或延迟写回后的输入失效流程不一致；统一 document_edited，并增加组合输入和跨块选择后的真实帧回归 |
| 渲染 | 同一 galley 参与呈现和点击映射，避免视觉与命中双实现 | 原块源码没有包含目录/引用/资源依赖；准备内容与缓存身份由渲染 module 一起管理 |
| 本地资源 | 合法本地 URI、现有原生加载器 | 同路径图片被覆盖后仍命中 egui 旧缓存；资源版本变化清除图片与相关高度 |
| 外部文件生命周期 | Document 已具有重载、三方合并、重新关联和保存冲突检测 | App 的全局错误标记受标签顺序影响；ExternalChanges 拥有节流、逐文档错误和冲突状态、解决动作 |
| 后台与扩展 | 后台线程只拥有输入；忙碌状态、断连恢复和扩展协议独立 | 旧结果丢失路径上下文；启动快照和返回 token 贯穿完整流程 |
| 单实例入口 | 有文件锁、请求格式与收件箱预算 | 两个各 80 文件请求被总 128 限额截断；改为每条请求保持 128 限制，完整返回已接受的收件箱内容 |
| 恢复 | 校验快照、保留不可读或未来版本数据、区分磁盘基线与本地草稿 | 定时、存储回调、退出三个调度入口仍在 App，部分退出错误处理较弱；本轮保留，见后续候选 |
| 导出与工作区 | HTML/PDF 有结构和图像回归；工作区扫描有深度/数量限制并跳过符号链接 | 重型导出、打印和工作区扫描仍同步执行，可能影响大任务响应；尚无本轮耗时复现，暂不声称已解决 |
| CI 与发布 | 三系统测试、Clippy、发布构建，依赖门禁、性能预算和三个 fuzz 目标 | 文档对模块划分与 fuzz 目标描述落后，已同步；本地检查不等于三平台 CI 或长时间 fuzz 已通过 |

## 实施后的协作规则

1. Document 捕获编辑前的真实正文；命令闭包操作工作副本，成功返回后才一起提交正文、历史、dirty 和派生失效。闭包 panic 不留下半更新文档。
2. 扩展和表格捕获文档快照。Session 按 token 定位文档并提交；目标关闭或版本不符时不会执行编辑闭包。另存为改变路径、编辑后撤销回原文、重载均使旧结果失效。
3. 成功写回通知 EditorSurface 清理旧 IME 和跨块选择，并钳位新选区。表格写回失败保留草稿和窗口，提供复制 Markdown 的出口。
4. ExternalChanges 统一自动扫描和人工解决动作，按文档 ID 管理错误去重；App 负责文件选择、确认与结果呈现。
5. 渲染准备统一确定目录内容、引用上下文和资源依赖，高度预测与测量使用相同的准备结果。本地图片状态探测节流，更新时清除旧图缓存。

这使一致性规则获得 locality：改动某项规则主要发生在其拥有者内部。文档命令、表格、扩展以及自动/人工外部变更共同复用这些接口，形成实际 leverage；测试直接作用于相同 interface，无需模拟整个窗口。

## 保留的限制与后续候选

- `Document.content/path/dirty/analysis` 等旧公开字段、Session 的可变借用仍保留兼容性。新命令已使用原子事务，但原生输入仍通过惰性缓冲 + record_edit 提交；类型系统还不能完全阻止调用者绕过约定。下一步应在迁移输入缓冲时一起收紧，避免每个空闲帧克隆全文。
- 图片版本检测依赖本地文件状态并经过节流，不是完整目录监听器；文件系统保存相同长度与时间戳的特殊覆盖需要额外策略。
- 恢复调度、同步导出及工作区扫描可以进一步收拢或后台化，应先测量实际阻塞并覆盖失败路径。
- 本轮没有将所有潜在问题称为已复现或已修复，也没有把原有大范围未提交改动计作本轮新增功能。
